# Contributing to Anon

First off, thank you for considering contributing to Anon! It's people like you that make Anon such a great tool for the privacy and security community.

## How Can I Contribute?

### Reporting Bugs
If you find a bug, please use the **Bug Report** issue template. Before opening an issue, please:
- Check if the issue has already been reported.
- Ensure you are running the latest version of Anon.
- Provide detailed steps to reproduce the issue.

### Suggesting Enhancements
We welcome new features and ideas! Please use the **Feature Request** issue template to pitch your idea before writing code to ensure it aligns with the project's roadmap.

### Pull Requests
1. **Fork the repository** and clone it locally.
2. **Create a branch** for your feature or bug fix (`git checkout -b feature/awesome-feature`).
3. **Commit your changes** with clear and descriptive messages.
4. **Push to your fork** (`git push origin feature/awesome-feature`).
5. **Open a Pull Request** against the `main` branch.

## Code Style
- Anon is written primarily in **Bash**.
- Ensure your code is clean, readable, and properly indented.
- Use `shellcheck` if possible to lint your scripts before submitting a PR.
- Add comments explaining complex logic, especially if dealing with `iptables` rules or low-level system changes.

Thank you for helping us keep the internet anonymous and secure!
